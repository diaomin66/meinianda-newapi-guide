MEINIANDA AI / QUICKSTART

从注册到首次调用，只需五分钟。

这份文档覆盖新用户完整路径、充值与到账口径、API Key 创建，以及 OpenAI、Claude、Gemini、图像、视频和向量模型的对接方式。

01

新用户完整使用流程

按顺序完成即可。模型可用范围由账户分组决定，先充值、再选模型，能减少首次接入中的权限与余额问题。

01

注册账户

访问注册页，设置用户名和密码；完成后进入控制台登录。

注册
02

打开 Wallet 并充值或兑换

在 Wallet 选择当时显示的支付方式；若有兑换码，也在此处完成兑换。

去钱包
03

创建 API Key

在 Keys 中新建密钥，复制一次并写入服务端环境变量。密钥泄露时立即删除重建。

创建 Key
04

从 Pricing 选择模型

检查模型名称、分组、倍率和支持协议；不要只凭模型名称猜接口类型。

选模型
05

发送首个请求并看日志

用模型卡给出的协议模板测试；成功后到用量日志核对模型、消耗与返回结果。

测试
i
安全边界：API Key 等同于账户调用权限。仅存放在服务端环境变量或密钥管理器中，不要写入前端、截图、浏览器扩展配置或公开仓库。
02

充值比例与到账说明

充值比例和支付方式会由站内配置调整。本页展示基础计算口径；付款前，以 Wallet 最终订单页显示的应付金额为准。

0.90来自 status.price
USD来自 quota_display_type
500,000每 1 显示额度对应 quota

基础充值公式

基础应付 = 充值显示额度 × 基础支付系数

基础系数 0.90 表示充值 1.00 显示额度对应基础应付 0.90。到账内部额度为“充值显示额度 × 500,000 quota”。若 Wallet 显示账户规则、最低充值额或活动优惠，最终订单金额以该页为准。

基础应付试算

基础应付（未计入组倍率/活动）0.00到账内部额度：0 quota
i
不要误标为某种支付币种：公开配置给出的是支付系数与显示额度，不足以确认实际结算币种；因此本页仅说明比例与公式，不把 0.90 写成某个法定货币金额。

所有调用都需要一枚在 Keys 页面创建的密钥。将 Base URL 与 Key 交给对应 SDK；模型名称由 Pricing 目录决定。

04

OpenAI 兼容接入

大部分文本模型可使用 OpenAI SDK。将 MODEL_ID 换成 Pricing 中实际可用的模型名称；密钥只应在服务端读取。


          
✓
首个请求的验收标准：HTTP 200、返回里包含你选定的 model、用量日志出现该次请求。若返回模型不可用，请先在 /v1/models 或 Pricing 中确认账户分组是否具备该模型。

文本 / 推理
openai
常规对话、推理、工具调用模型优先使用 OpenAI Chat Completions。
POST /v1/chat/completions

            
Responses
responses
仅限模型卡包含 Responses 标签的模型；compact 是独立路由。
POST /v1/responsesPOST /v1/responses/compact

            
Claude Messages
anthropic

Gemini 原生
gemini

07
常见问题与排错

          
为什么返回“模型不可用”或找不到模型？
先检查模型 ID 是否完全一致，再用 GET /v1/models 查询当前 Key 实际可用的列表。若模型在 Pricing 中存在但 Key 看不到，通常是分组、余额或模型状态发生变化。

          
充值后没有立即到账怎么办？
先保留支付订单信息，在 Wallet 的充值记录中查看状态。不要重复支付；最终以 Wallet 订单、到账记录和平台支持渠道的核验结果为准。

          
模型倍率和充值比例是一回事吗？
不是。充值比例决定购买显示额度时的基础应付公式；模型倍率决定具体调用时的消耗计算。模型卡显示的是后者，支付页显示的是前者。

          
能把 API Key 放到网页、移动端或浏览器插件里吗？
不建议。任何能被最终用户查看或提取的前端环境都可能泄露 Key。请用自有后端代理请求，或为不同环境创建可随时撤销的独立 Key。
